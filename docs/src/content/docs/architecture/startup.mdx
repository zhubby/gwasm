## 1. 同步启动阶段

`gwasm.py` 先检查 Python 版本与 release 必需文件，解析 `--origin` 和并发上限，建立 `dist/` 与缓存目录。`publish()` 把 harness 和字体复制到运行目录，`copy_art()` 生成只包含本地图片文件名与署名的索引。之后才绑定端口并计算实际 Origin。

ServerContext 是每个 server instance 的状态边界：进度、ChunkStore、relay policy、允许的 Origins、HTTP client 和 watchdog 都不放在模块全局，因此测试可以并行启动不同策略的实例。

## 2. 后台更新阶段

HTTP 服务先启动，更新工作在线程中进行，加载页通过 `/progress.json` 展示版本、下载速率和 ETA。更新异常时：

- `dist/` 已有客户端：记录错误并继续，保留可用版本；
- 没有客户端：将进度标记为 error，页面保持明确失败状态；
- 离线且无 snapshot index：不能构造虚拟快照，启动不宣称 ready。

## 3. 浏览器启动阶段

`harness-boot.js` 等待更新完成，读取 `snapshot-chunks.json`，使同步 `image.fileSize()` 在 glue 执行前就能返回。随后按平台能力选 JSPI 或 Asyncify、安装 `instantiateWasm()` 与 `locateFile()`，最后装载官方 glue。

<Aside type="caution" title="脚本顺序是 ABI 的一部分">
`harness.js`、cache、Module、input、boot 是有序 classic scripts。`Module` 必须是顶层 `var`，改成 ESM、`const` 或异步无序加载都可能让 glue 创建另一个空对象。
</Aside>

## 4. 生命周期与心跳

游戏页和文档页都向 `/ping` 发送标签页身份。`pagehide` 发送 `bye=1`，watchdog 延迟确认，以容纳 reload；150 秒 idle 容差覆盖浏览器后台标签计时器降频。只有由启动器自动打开浏览器时才启用 watchdog，`--no-browser` 的服务不会因为无人查看文档而自行退出。
