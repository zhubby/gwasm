gwasm 把原本位于 Capacitor WebView 与原生移动壳中的职责，拆成浏览器宿主和本机 Python 服务。浏览器运行未经重写的 Emscripten glue 与 Wasm；Python 负责浏览器不能或不应直接完成的持久缓存、TCP 连接、DNS 兼容和上游 HTTPS 转发。

<ArchitectureDiagram type="context" lang="zh" />

图中箭头是主请求方向，不代表所有回调。浏览器与 Python 之间保持同源：静态资源、`/progress.json`、`/dns`、Range、proxy 与 WebSocket relay 全部共享一个 Origin，因此不依赖 CORS。Python 到外部服务的边界则由域名、端口、地址类型和显式路由共同约束。

## 进程与所有权

| 区域 | 拥有的状态 | 明确不拥有 |
| --- | --- | --- |
| `gwasm.py` | CLI、生命周期、发布目录、ServerContext | 浏览器 UI 状态、账号凭据 |
| `gwasm_core` | HTTP、manifest/chunk、Range、DNS/proxy/relay | 第三方包、Node 运行时 |
| `harness/` | `Module.*`、缓存、输入、EGL 呈现、加载状态 | 原始 TCP、磁盘文件路径 |
| Wasm 客户端 | 游戏逻辑、渲染调用、协议状态 | 浏览器平台能力实现 |
| `docs-dist/` | 版本化静态文档 | `/data` 持久卷、运行时写入 |

## 两条平面

**控制平面**负责版本选择、manifest 解析、hash 校验、进度、Origin 和策略。**数据平面**负责把 Wasm 的任意 offset/length 读取转换成 256 KB 内容块；它跨浏览器内存、Cache API、Python 磁盘缓存和 CDN 四层，但每层都用相同 hash 标识内容。

<Aside type="note" title="部署文档不是另一个服务">
Astro/Starlight 只在构建阶段运行。生产中的 `/docs/*` 由同一个 Python Handler 从只读 `docs-dist/` 提供，运行镜像不包含 Node/npm。
</Aside>

## 故障隔离

文档缺失不会阻止游戏启动；客户端更新失败时，如果已有可用客户端则继续运行；预热失败也不会阻止按需读取。相反，hash 不匹配、缺失 snapshot index、越界 Range、非法 Origin 或私网 relay 目标会显式失败，因为继续执行会破坏数据完整性或安全边界。
